# SCENES（模板）

> **制作主入口。一场景一卡：先画出结果，再拆素材和交互。**
> 复制下面的场景卡使用。场景少时都放在本文件；过多时再按场景拆分。
> 本项目里场景卡与设计稿 SVG 一一对应：稿子根节点写 `data-scene-id="SC-xxx"`，场景卡的「场景图」字段填稿子路径。

## 场景索引

| 场景 ID | 名称 | 设计稿 | 优先级 | 素材审核 | 实机验收 | 状态 |
|---|---|---|---|---|---|---|
| SC-001 | | `screens/xxx.svg` | P0 | 未审 | 未测 | 设计中 |

状态只用：`设计中 → 待素材 → 待审核 → 可实现 → 已验收`。返修时回到 `待素材`。

## SC-xxx：场景名

### 1. 场景定义

| 项 | 内容 |
|---|---|
| 玩家目标 | 玩家在这里要完成什么 |
| 关联玩法 / 参数 | M01；P001 |
| 设计稿 | 相对项目目录的稿子路径，如 `screens/main-menu.svg`（viewBox 即设计分辨率） |
| 适配范围 | 目标分辨率、横竖屏、缩放 / 裁切策略 |
| 安全区 | 四边留白；刘海、系统栏等限制 |
| 稿子版本 | 与稿子根节点 `data-version` 一致，审核单必须对应同一版本 |

### 2. 场景图

最终希望看到的画面；不能用单张角色立绘代替完整场景。

- 设计稿 SVG：`screens/xxx.svg`（在工作台查看器里看，语义标注清单就是布局标注）
- 合成预览 / 效果图（可选）：`assets/scene/SC-xxx/scene.png`

- [ ] 已画完整场景，而不是素材散图
- [ ] 稿子根节点已写 `data-scene-id`，与场景卡 ID 一致
- [ ] 占位素材已明确标记（文件名 `placeholder-` 开头），不会误认为正式素材

### 4. 交互逻辑
