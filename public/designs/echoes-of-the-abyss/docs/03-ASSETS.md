# ASSETS（模板）

> 素材从场景卡拆出。**可用 = 技术检查通过 + 场景内人工审核通过 + 文件进入 approved。**
> 本项目素材位于 `public/designs/<项目>/assets/`，按生命周期分四层；跨项目共享素材放 `public/assets/`，分层规则相同。

## 一、生产与审核链路

```text
场景卡 → 素材生产卡 → raw 原始产出 → 机器检查 / 修正
→ 拼回设计稿 → 人填写审核单 → approved → 实现侧复验
```

```text
assets/ref        风格参考，只读，不进游戏
assets/raw        原始产出，不能进正式稿
assets/scene      场景效果图、标注图、素材合成预览
assets/approved   人工通过的素材，正式稿只认这里
docs/review/      人工审核记录
```

四层是固定约束，**层内子目录自由创建**（如 `raw/components/`、`raw/ui/`、`approved/icons/`）；素材审核状态由所在层推导，与子目录名无关。

AI 可以生成、修图、整理和拼装，但**不能代替人审核通过**。

## 二、风格参考

环境和角色画法不同，按类型选参考，不拿角色图去生成地面。

| 文件 | 管什么 | 挑图标准 |
|---|---|---|
| `ref/anchor.png` | 场景材质、光照、色温 | 含地形、建筑或主体物件，能继续生成同类环境 |
| `ref/ref-card.png` | 角色比例、剪影、描边 | 完整身形、轮廓清楚，能继续生成同风格角色 |

参考图只定调，不进 `approved/`。更换参考前，把原因和影响记进 `04-DECISIONS.md`。

## 三、素材生产卡

每个正式素材一张。先做一件小样并拼进场景，小样通过后再批量生产。

### A001：素材名

| 项 | 要求 |
|---|---|
| 所属场景 / 元素 ID | SC-xxx / 区域 ID |
| 来源 | AI 生成 / 手绘 / 外包 / 合法素材库 |
| 参考文件 | `assets/ref/...`，可附局部参考 |
| 提示词或绘制要求 | 主体、动作、材质、背景；AI 生成时保留完整提示词 |
| 风格约束 | 视角、光源、色板、描边、比例 |
| 内容尺寸 / 导出尺寸 | 主体实际像素 / 文件画布像素 |
| 格式 / 透明要求 | png、是否透明、九宫格等 |
| 锚点 / 标准留白 | |
| 状态帧 / 动画帧 | 默认、按下、禁用等；列出帧数和命名 |
| raw 输出路径 | `assets/raw/...` |
| 对应场景预览 | `assets/scene/SC-xxx/...` |

禁止只写「做一张好看的图」。没有场景、尺寸和参考，就不能开始批量生产。

## 四、机器检查：只证明文件合格

`npm run check` 校验设计稿标注规范；素材本身的尺寸、透明边、帧完整性可在工作台清单里人工核对，也可由脚本辅助修正。自动修正不等于审核通过。

| 检查项 | 通过标准 |
|---|---|
| 文件 / 命名 | 可读取，格式和命名符合生产卡（kebab-case，如 `knight-ashfall-full.png`） |
| 尺寸 | 导出尺寸、帧尺寸、九宫格信息符合要求 |
| 透明与边界 | 需要透明的素材有 alpha；无异常白边、脏边、意外裁切 |
| 内容完整性 | 主体、状态帧、动画帧齐全，没有缺图 |
| 引用 | 正式稿仅引用 `assets/approved/`：引用 `ref/` `scene/` 报错（SVG013/014），引用 `raw/` 提示（SVG105） |

风格、语义、遮挡和实际可读性不得由脚本代替人判断。

## 五、人工审核：正式入口

1. 复制 `docs/review/_TEMPLATE.md` 为 `docs/review/SC-xxx.md`。
2. 审核人同时查看：风格参考、素材缩略图、最新设计稿；音效在对应场景试听。
3. 对每个素材选 **通过 / 驳回**；驳回必须写一句可执行的修改意见。
4. 场景整体也要审核：风格统一、主体清晰、层级正确、语义明确、交互可辨认。
5. 只有审核人明确通过后，素材才可进入 `approved/`；工具可代为移动，但不得代签。

可以按场景集中看图，**不能跳过人工审核**。返修后更新稿子版本，只重审受影响素材和整体画面。
